# GCP 疎通確認（1台版）── litellm → Vertex の1往復を確かめる

*個人検討ノートの一般化版（2026-11-18 同期・正は個人 Vault）*

> [!NOTE]
> **このドキュメントの位置づけ**
> **1台版（お試し・`compose.single.yaml`）**で、鎖の右端＝LiteLLM → GCP Vertex AI の疎通を確かめる独立手順。[開発環境構築](00_環境構築手順.md) §5.2・§5.4 の疎通部分を「上から順に実行できる形」に抜き出した。GCP 側の準備（プロジェクト・API 有効化・認証方式の選定）は [GCP/Vertex AI準備](01_GCPとVertexAI準備.md) が正典＝完了している前提。

## 1. 前提

- `.env` に `VERTEX_PROJECT`（GCP プロジェクト ID）と `LITELLM_MASTER_KEY` が入っている（[開発環境構築](00_環境構築手順.md) §6）。
- `litellm_config.yaml` に論理名 `gemini`（`vertex_ai/gemini-…`）が定義されている（同 §5.3。**モデル名は生もの**＝実行前に現行かを GCP準備 §3.7.1 の手順で再確認）。
- ホストに gcloud CLI 導入済みで、ADC を作ってある：

```bash
gcloud auth application-default login
```

## 2. ADC を litellm コンテナへつなぐ（初回のみ）

`compose.single.yaml` の litellm サービスに、ADC の読み取り専用マウントと環境変数を足す（開発環境構築 §5.4.1 と同じ追記。★`~` の展開は実機で確認）：

```yaml
    volumes:
      - "../litellm_config.yaml:/app/config.yaml:Z"
      - "~/.config/gcloud/application_default_credentials.json:/app/adc.json:ro"
    environment:
      - GOOGLE_APPLICATION_CREDENTIALS=/app/adc.json
```

## 3. 1台版で起動する

```bash
cd .devcontainer && docker-compose -f compose.single.yaml up -d --build
```

4サービス（gateway・web・litellm・db＝1台版は Redis 不要）が Up（db・litellm は `healthy`）になるのを待つ：

```bash
docker-compose -f compose.single.yaml ps
```

## 4. 疎通を内側から順に確かめる

**①プロセス生存**（認証不要・"I'm alive!" が返る）：

```bash
curl -s http://localhost:4000/health/liveliness
```

**②master key をシェルに読み込む**（値を画面に出さない作法）：

```bash
export LITELLM_MASTER_KEY=$(grep '^LITELLM_MASTER_KEY=' ../.env | cut -d= -f2-)
```

**③モデル一覧**（論理名 `gemini` が見えるか）：

```bash
curl -s -H "Authorization: Bearer $LITELLM_MASTER_KEY" http://localhost:4000/v1/models
```

**④本番の1往復**（ダミー文のみ・`max_tokens` は小さく）：

```bash
curl -s http://localhost:4000/v1/chat/completions -H "Content-Type: application/json" -H "Authorization: Bearer $LITELLM_MASTER_KEY" -d '{"model":"gemini","messages":[{"role":"user","content":"疎通確認のダミー文です。OKとだけ返してください。"}],"max_tokens":16}'
```

200 で本文と `usage`（トークン数）が返れば、**litellm → service account/ADC → Vertex の鎖が通っている**。

## 5. おまけ：spend が台帳（Postgres）に載るのを見る

④の後、支出ログが DB に書かれる——ただし**書き込みはインターバル実行のバッチ**なので、即時には増えない（[解説01 利用管理](../05_論点解説/01_利用管理（使用制限・記録DB・仮想キー）.md) §1.2＝鮮度論点をここで実地に見られる）。少し待ってから件数を数える：

```bash
docker-compose -f compose.single.yaml exec db psql -U litellm -c 'SELECT COUNT(*) FROM "LiteLLM_SpendLogs";'
```

VS Code の SQLTools（キットの拡張）で `db:5432` を開いて眺めてもよい。

## 6. つまずき

- **④が 401**：master key（②の読み込み・`.env` の値）を見直す。
- **④が 404（model not found）**：`litellm_config.yaml` の `model_name: gemini` と、`-d` の `"model":"gemini"` が一致しているか。
- **④が Vertex の認証エラー**：ADC マウント（§2）・`VERTEX_PROJECT`・GCP 側の API 有効化（GCP準備 §3）を順に。
- **④がモデル名エラー**：実モデル名の鮮度切れを疑う＝GCP準備 §3.7.1 で現行名を確認して config を直す。
